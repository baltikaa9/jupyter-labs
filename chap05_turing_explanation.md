## 1. Что такое машина Тьюринга

У машины есть три основные части:

- **Лента** — последовательность клеток с символами `0` и `1`. Теоретически она
  бесконечна в обе стороны. Изначально все клетки содержат нули.
- **Головка** — указывает на одну клетку, читает и изменяет её. Может перемещаться
  на одну позицию вправо или влево.
- **Состояние** — текущий режим работы: `A`, `B` или `C`. Это не символ ленты.

В отличие от клеточного автомата из первого упражнения, здесь за один шаг
обрабатывается только клетка под головкой, а не вся строка одновременно.

## 2. Таблица команд

Команду выбираем по двум значениям: **текущее состояние и символ под головкой**.
Она определяет, что записать, куда переместиться и в какое состояние перейти.

| Состояние | Прочитано | Записать | Движение | Новое состояние |
|---|---:|---:|---|---|
| A | 0 | 1 | вправо | B |
| A | 1 | 1 | вправо | HALT |
| B | 0 | 0 | вправо | C |
| B | 1 | 1 | вправо | B |
| C | 0 | 1 | влево | C |
| C | 1 | 1 | влево | A |

Например, `(A, 0) → (1, вправо, B)` означает: если машина в состоянии `A`
читает `0`, записать `1`, передвинуть головку вправо и перейти в `B`.

В коде эта команда записана так:

```python
("A", 0): (1, 1, "B")
```

Внутри результата первый `1` — записываемый символ, второй `1` — направление.
Для направления `1` означает вправо, `-1` — влево.
`HALT` — остановка, а не четвёртое рабочее состояние.

## 3. Что такое «усердный бобр»

В варианте задачи, который здесь используется, среди останавливающихся машин
с заданным числом рабочих состояний ищут ту, которая оставляет больше всего
единиц на изначально пустой двоичной ленте.

Используем известную таблицу для трёх состояний. Она оставляет **6 единиц**
и останавливается через **14 шагов**. Числа не зашиты в алгоритм остановки:
машина выполняет команды до состояния `HALT`, а затем мы проверяем результат.
14 — время работы именно этой таблицы, не максимальное время всех трёхсостоянийных машин.

## 4. Что хранит класс `Turing`

| Атрибут | Назначение | Начальное значение |
|---|---|---|
| `tape` | Словарь «позиция → символ» | `{}` |
| `head` | Положение головки | `0` |
| `state` | Текущее состояние | `"A"` |
| `steps` | Количество выполненных команд | `0` |
| `history` | Снимки работы для рисунка | Снимок начального состояния |

Почему лента — словарь, а не список? Позиции могут быть отрицательными, например
`-1`, `-2`. В словаре это обычные номера клеток, а в списке отрицательные индексы
обозначали бы элементы с конца списка.

```python
symbol = self.tape.get(self.head, 0)
```

Здесь `get` читает символ под головкой. Если позиции ещё нет в словаре,
возвращается `0`: незаписанные клетки считаются пустыми. Так не нужно заранее
выделять бесконечный массив — память используется только для записанных клеток.

## 5. Как работает `step()`

Главные строки метода:

```python
symbol = self.tape.get(self.head, 0)
write, move, next_state = self.rules[self.state, symbol]
self.tape[self.head] = write
self.head += move
self.state = next_state
```

По порядку:

1. Читаем текущую клетку.
2. Получаем команду из таблицы `rules`.
3. Записываем символ в старую позицию головки.
4. Перемещаем головку.
5. Меняем состояние.
6. Увеличиваем `steps` и сохраняем снимок.

Даже если новое состояние — `HALT`, запись и движение этой последней команды
выполняются. При следующем вызове `step()` машина уже ничего не меняет
и возвращает `False`.

### Первые три шага вручную

| Шаг | До команды: состояние, позиция, символ | Что происходит | После команды |
|---:|---|---|---|
| 1 | A, 0, 0 | Записать 1, вправо | B, позиция 1 |
| 2 | B, 1, 0 | Записать 0, вправо | C, позиция 2 |
| 3 | C, 2, 0 | Записать 1, влево | C, позиция 1 |

После трёх шагов в клетках `0, 1, 2` находятся `1, 0, 1`.
Головка стоит в клетке `1`, состояние — `C`.

## 6. Зачем нужны `run()` и история

`run()` вызывает `step()` до перехода в `HALT`. Параметр `max_steps=1000`
ограничивает число дополнительных команд, чтобы при изменении правил ноутбук
не завис в бесконечном цикле. Если лимит достигнут без остановки, возникает ошибка.
Это ограничитель выполнения, а не доказательство, что машина никогда не остановится.

`save_state()` сохраняет ленту, положение головки, состояние и номер шага.
Для ленты используется `self.tape.copy()`: нужен отдельный снимок словаря,
иначе последующие записи изменяли бы и старые состояния на рисунке.

Сохраняем начальное состояние и результат каждой команды, поэтому после
14 шагов в истории **15 снимков**.

## 7. Что показывает `TuringViewer`

`TuringViewer` не выполняет команды — он только рисует сохранённую историю.

- По горизонтали — позиции клеток ленты, включая отрицательные.
- По вертикали сверху вниз — количество уже выполненных шагов: от 0 до 14.
- Белая клетка — `0`, серая — `1`.
- Красный квадрат — положение головки.
- Красная буква внутри — состояние `A`, `B`, `C` или `HALT`.

Каждая строка — **вся показанная часть ленты в данный момент**, а не одна команда.
По рисунку можно проследить перемещение головки и появление единиц.

## 8. Результат и проверки

Для выбранной таблицы получаем:

```text
Состояние: HALT
Выполнено шагов: 14
Единиц на ленте: 6
Положение головки: 2
```

Единицы находятся в позициях от `-1` до `4` включительно; остальные клетки — нули.
Число единиц считаем через `sum(machine.tape.values())`, потому что символы — 0 и 1.

`assert` в последней ячейке проверяет остановку, 14 шагов, 6 единиц, сохранность
начального снимка и отсутствие дальнейшей работы после `HALT`.

**Коротко для защиты:** реализована машина Тьюринга с двоичной лентой и тремя
рабочими состояниями. Команда определяется состоянием и прочитанным символом.
Выбранный усердный бобр остановился за 14 шагов, оставив 6 единиц.
Визуализатор показывает всю историю ленты и головки. Запуск подтверждает работу
этой таблицы, но сам по себе не доказывает её оптимальность среди всех машин.

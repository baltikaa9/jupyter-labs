# Лабораторная №4: объяснение упражнения 3 — генераторы случайных чисел

## Что требовалось сделать

Реализовать линейный конгруэнтный генератор, узнать алгоритм Python `random`,
получить последовательность из центральной клетки Правила 30 и проверить
все три генератора через DieHarder.

В `chap05_exercises.ipynb` решение разбито на четыре ячейки:
генераторы, проверки кода, сохранение данных, запуск DieHarder.
Для работы достаточно выполнить начальную ячейку с импортами и эти четыре ячейки.
Первое и второе упражнения выполнять не обязательно.

## 1. Что означает «псевдослучайный»

Следующее число получается по определённому алгоритму. Последовательность может
выглядеть случайной, но при одинаковом начальном состоянии повторяется.

`seed` — начальное значение, от которого зависит последовательность.
Фиксированное значение удобно для проверки и воспроизведения эксперимента.
В ЛКГ и `random` используем `seed=1`. У Правила 30 начальное состояние другое:
одна единица в центре строки, остальные клетки — нули.

## 2. Линейный конгруэнтный генератор — `lcg_words`

Формула:

```text
x_next = (a * x + c) % m
```

Используем параметры Numerical Recipes:

- `a = 1664525` — множитель;
- `c = 1013904223` — прибавляемая константа;
- `m = 2**32` — модуль;
- `x = 1` — начальное значение.

Операция `% m` оставляет остаток от деления, поэтому результат лежит
от `0` до `2**32 - 1`, то есть помещается в 32 бита.

Первое число: `(1664525 * 1 + 1013904223) % 2**32 = 1015568748`.
Чтобы получить второе, подставляем первое вместо `x`, и так далее.

При этих параметрах полный период равен `2**32`, но это не означает высокого качества.
Например, обе константы нечётные, поэтому последний бит числа просто чередуется:
`0, 1, 0, 1, ...`. У других младших битов тоже короткие периоды.

## 3. Python `random` — `mt_words`

Основной генератор модуля — **Mersenne Twister, MT19937**.

```python
rng = random.Random(1)
number = rng.getrandbits(32)
```

Первая строка создаёт отдельный генератор с начальным значением 1.
Вторая возвращает 32-битное неотрицательное целое число.
Отдельный объект не меняет состояние общего генератора `random` в других ячейках.

Период MT19937 равен `2**19937 - 1`. Это значительно больше, чем у выбранного ЛКГ,
но ни большой период, ни прохождение статистических тестов не делают его
криптографически безопасным. Для паролей и токенов нужен, например, `secrets`.

## 4. Правило 30 — `rule30_bits` и `rule30_words`

Используем строку из **501 клетки**. Изначально в центре одна единица.
После каждого шага записываем новое значение центральной клетки:

```text
шаг 1 → один бит
шаг 2 → следующий бит
...
```

Число 30 задаёт таблицу переходов для соседей `111, 110, 101, 100, 011, 010, 001, 000`:
результаты равны `0, 0, 0, 1, 1, 1, 1, 0`.
Эквивалентная формула для центральной клетки:

```text
новое значение = левый сосед XOR (сама клетка OR правый сосед)
```

В Python `^` — XOR, `|` — OR. Новая строка вычисляется целиком из старой.

### Почему в коде целое число вместо массива

Python поддерживает целые числа произвольной длины. Одно число может хранить
501 бит — по одному на клетку. Так можно одновременно обновлять все клетки
побитовыми операциями, не создавая массив истории.

- `1 << center` помещает начальную единицу в центральную позицию.
- `state << 1` и `state >> 1` сдвигают биты для получения соседей.
- Дополнительные операции переносят крайние биты на противоположный край:
  **строка замкнута в кольцо**.
- `mask = (1 << width) - 1` — число из 501 единицы; `& mask` отбрасывает лишние биты.
- `(state >> center) & 1` извлекает центральную клетку.

Это конечный автомат с периодическими границами, а не бесконечная строка.
После распространения возмущения до границ они влияют на дальнейшую эволюцию.
Его статистические свойства необходимо проверять, а не предполагать заранее.

### Как биты превращаются в число

`rule30_words` объединяет каждые 32 последовательных бита:

```python
word = (word << 1) | bit
```

Сдвиг освобождает место справа, затем туда добавляется новый бит.
Первый из 32 битов становится старшим. Например, последовательность
`1, 0, 1` при таком накоплении даёт двоичное `101`, то есть число 5.

## 5. Какие проверки выполняет ноутбук

- Первые три числа ЛКГ сверяются с ожидаемыми значениями.
- Битовая реализация Правила 30 сравнивается с независимой реализацией через
  таблицу переходов на строках шириной 7, 17 и 501.
- Проверяется порядок упаковки центральных битов в числа.
- Повторный запуск генератора даёт такое же начало последовательности.
- Числа находятся в диапазоне `0 <= x < 2**32`.
- Размер файлов и первые записанные числа совпадают с ожидаемыми.

**Это проверки правильности программы, а не доказательство случайности.**

## 6. Какие файлы создаются

В каталоге `data/prng/`:

| Файл | Генератор |
|---|---|
| `lcg.bin` | Линейный конгруэнтный |
| `python_random.bin` | Mersenne Twister из Python |
| `rule30.bin` | Центральная клетка Правила 30 |

Это двоичные файлы без заголовка, а не текстовые списки чисел.
Каждое число записывается как беззнаковое 32-битное целое: **4 байта**.
Используется порядок байтов текущей машины (`dtype="=u4"`), соответствующий
чтению raw-файла DieHarder в том же окружении.

В выполненном эксперименте `N_WORDS = 2**24`: каждый файл содержит 16777216 чисел
и занимает **64 МиБ**. Для Правила 30 это `32 * 2**24 = 536870912` шагов
и столько же центральных битов. Генерация Правила 30 заняла около 356 секунд.
Для быстрой демонстрации можно поставить `N_WORDS = 2**18` (1 МиБ), но тогда
последняя ячейка не запускает статистические тесты из-за малого объёма данных.
Данные генерируются и записываются порциями, без хранения всей истории автомата.
Повторный запуск перезаписывает эти три файла. Каталог исключён из Git как
воспроизводимые результаты эксперимента.

В таблице также показывается доля единиц во всех битах файла.
Значение около 0.5 — только предварительный признак: даже чередование `010101...`
имеет ровно половину единиц, но совершенно предсказуемо.

## 7. Проверка через DieHarder

**DieHarder 3.31.1 установлен; выполнены шесть настоящих тестов на файлах по 64 МиБ.**
Результаты сохранены в выводе ноутбука и журналах `data/prng/*_test_*.txt`.

На Arch Linux программа доступна в AUR:

```bash
yay -S dieharder
```

Это системная программа, не Python-пакет: через `uv` ничего устанавливать не нужно.
Ноутбук сам ничего не устанавливает. Для повторения эксперимента:

1. Оставить в третьей ячейке решения `N_WORDS = 2**24` — по 64 МиБ данных.
2. Повторить генерацию. Правилу 30 потребуется `2**29` шагов; это может занять
   несколько минут или больше в зависимости от компьютера.
3. Выполнить последнюю ячейку: она запускает одинаковые тесты для всех генераторов
   и сохраняет вывод в `data/prng/*_test_*.txt`.

Выбраны два теста: **Birthdays**, идентификатор 0, и **Binary Rank 32x32**,
идентификатор 2. Это ограниченная ознакомительная проверка, не полная батарея.

Пример ручного запуска из каталога ноутбука после генерации достаточного объёма:

```bash
dieharder -g 201 -f data/prng/lcg.bin -d 0 -p 5
dieharder -g 201 -f data/prng/lcg.bin -d 2 -p 5
```

Для других генераторов заменить имя файла на `python_random.bin` или `rule30.bin`.
Команды для всех трёх файлов напечатаны в последней ячейке.

- `-g 201` — читать необработанные двоичные данные из файла;
- `-f` — путь к файлу;
- `-d` — идентификатор теста;
- `-p 5` — пять p-выборок для короткой проверки; это не пять чисел на входе.

64 МиБ — стартовый объём для этих настроек, не гарантия для любых версий
и параметров DieHarder. Программа может писать `file ... was rewound N times`.
Если `N > 0`, она многократно использовала одни и те же данные: такую оценку
нельзя считать надёжным результатом проверки независимых новых данных.
Нужно увеличить файл и повторить тест. Для полной батареи `-a` данных нужно
существенно больше; в учебном запуске она автоматически не запускается.

### Как читать результаты

- `PASSED` — тест не обнаружил значимого отклонения при выбранных настройках.
- `WEAK` — пограничный результат, требующий проверки на новых данных.
- `FAILED` — обнаружено отклонение; нужно также исключить ошибки формата
  и повторное чтение короткого файла.

Одиночные слабые результаты возможны даже у хороших генераторов.
Прохождение нескольких тестов не доказывает идеальную случайность
или пригодность для криптографии.

### Фактические результаты

Использованы начальные состояния, описанные выше, и одинаковые параметры
`-g 201`, `-p 5` для каждого генератора.

| Генератор | Тест | p-value | Оценка |
|---|---|---:|---|
| ЛКГ | Birthdays | 0.99320508 | PASSED |
| ЛКГ | Binary Rank 32x32 | 0.76185391 | PASSED |
| Python `random` | Birthdays | 0.97415423 | PASSED |
| Python `random` | Binary Rank 32x32 | 0.99755408 | WEAK |
| Правило 30 | Birthdays | 0.35440977 | PASSED |
| Правило 30 | Binary Rank 32x32 | 0.96042416 | PASSED |

Сообщений о повторном чтении файлов с ненулевым счётчиком в журналах не обнаружено.
Явного сообщения `rewound 0 times` эта версия при данном запуске тоже не вывела;
поэтому ячейка предлагает проверить журналы, а не подставляет выдуманный счётчик.

`p-value` — не оценка качества по шкале «чем больше, тем лучше».
В частности, значение 0.99755408 близко к верхнему краю диапазона и помечено
программой как `WEAK`. Это пограничное отклонение в одном коротком тесте,
а не доказательство непригодности Mersenne Twister. Для проверки устойчивости
результата нужны другие участки последовательности, начальные состояния
и больше p-выборок. Исходный результат сохранён, а не заменён удачным повтором.

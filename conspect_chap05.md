# Конспект: клеточные автоматы (гл. 5)

## Основные понятия

- **Клеточный автомат (КА)** — набор клеток, состояния которых обновляются по локальному правилу. В одномерном КА клетки расположены в строку; все новые значения вычисляются из предыдущей строки одновременно.
- **Элементарный КА** — одномерный автомат с состояниями 0 и 1, где новое значение зависит от самой клетки и двух соседей. Есть 8 комбинаций соседства и 2^8 = 256 правил.
- **Номер правила** кодирует таблицу переходов: для соседств `111, 110, 101, 100, 011, 010, 001, 000` Правило 110 дает `01101110`, Правило 30 — `00011110`.
- **Реализация в практике:** `np.correlate(row, [4, 2, 1], mode="same")` превращает каждую тройку в индекс 0…7, затем `table[index]` определяет новое состояние. За границами строки предполагаются нули.
- **Фон** — пространственно и во времени повторяющийся узор. **Корабль** — локализованная структура, повторяющаяся через T шагов со сдвигом d; скорость v = d/T. Положительная скорость — вправо, отрицательная — влево.
- **Границы влияют на результат:** в задании 1 исследуется центр широкой строки, куда влияние краев еще не дошло; в задании 3 края соединены в кольцо.

## Задание 1. Правило 110 и корабли

- Фон задается повторением блока `00010011011111`. Пространственный период — **14 клеток**, временной — **7 шагов**.
- В середину фона вставляются короткие шаблоны. После переходного процесса проверяется равенство `a(t + T, x + d) = a(t, x)` на исследуемом участке для многих последовательных моментов времени.

| Вставка | Период T | Сдвиг d | Скорость v |
|---|---:|---:|---:|
| `0001110111` | 3 | 2 | 2/3 |
| `1001111` | 30 | −8 | −4/15 |
| `111` | 7 | 0 | 0 |

- Перебраны **256 восьмибитных вставок**. У 84 подтверждено повторение со сдвигом; получено 5 разных пар (T, d). Это не означает, что найдено ровно 5 типов одиночных кораблей: объекты могут различаться или состоять из нескольких структур.
- Наибольший измеренный размах нарушения фоновой периодичности — **37 клеток**, вставка `11101010`, T = 10, d = 2, v = 1/5. Размах измеряется по крайним позициям, где `a(x) != a(x + 14)`; это максимум среди проверенных вставок, а не среди всех возможных кораблей.
- Столкновение `0001110111` и `00000011` дает структуру с T = 3, d = 2. Столкновение неподвижной `111` и леводвижущейся `00000011` дает структуру с T = 10, d = 2. Результат зависит от начальных шаблонов, их фаз и расстояния.

## Задание 2. Машина Тьюринга и усердный бобр

- **Машина Тьюринга** — лента с символами, головка и внутреннее состояние. За шаг обрабатывается одна клетка. Команда по паре «состояние, прочитанный символ» определяет запись, движение и следующее состояние.
- Используются три рабочих состояния A, B, C и остановка `HALT`. Изначально лента нулевая, головка в позиции 0, состояние A.

| Состояние | Прочитано | Записать | Движение | Следующее состояние |
|---|---:|---:|---|---|
| A | 0 | 1 | Вправо | B |
| A | 1 | 1 | Вправо | HALT |
| B | 0 | 0 | Вправо | C |
| B | 1 | 1 | Вправо | B |
| C | 0 | 1 | Влево | C |
| C | 1 | 1 | Влево | A |

- **Усердный бобр:** в используемом варианте задачи среди останавливающихся машин с заданным числом состояний ищут оставляющую больше всего единиц на изначально нулевой ленте. В работе моделируется уже выбранная таблица.
- Лента — словарь `tape`: координата → символ. `tape.get(head, 0)` считает отсутствующие клетки нулевыми. Поддерживаются отрицательные координаты, память выделяется по мере записи.
- `step()` читает клетку, выбирает команду, записывает символ, двигает головку и меняет состояние. `run()` повторяет шаги до `HALT`; лимит выполнения защищает от слишком долгого запуска, но не доказывает бесконечность работы.
- `history` хранит снимки с `tape.copy()`, чтобы последующие записи не меняли прошлые состояния. `TuringViewer` показывает позиции клеток по горизонтали, время сверху вниз; красным отмечены головка и ее состояние.
- **Результат:** остановка за **14 шагов**, **6 единиц** в позициях −1…4, головка в позиции 2. На рисунке 15 строк: начальное состояние и 14 результатов команд. Числа получены выполнением правил; 14 не является максимальным временем работы всех трехсостоянийных машин.

## Задание 3. Генераторы псевдослучайных чисел

- **Псевдослучайная последовательность** вычисляется алгоритмом и воспроизводится при одинаковом начальном состоянии. `seed` задает начальное состояние генератора.
- **ЛКГ:** `x_next = (1664525*x + 1013904223) % 2**32`, начальное x = 1. Первые числа: 1015568748, 1586005467, 2165703038. Результат лежит в диапазоне 0…2^32−1.
- Недостаток выбранного ЛКГ: обе константы нечетные, поэтому четность x меняется на каждом шаге, а младший бит чередуется. Большой период всей последовательности не исключает простых закономерностей отдельных битов.
- **Python `random`** использует Mersenne Twister (MT19937). `random.Random(1)` создает отдельный генератор, `getrandbits(32)` получает 32-битное число. Он не предназначен для криптографии.
- **Правило 30:** 501 клетка, одна единица в центре, границы замкнуты. Новая клетка = `левый XOR (текущая OR правый)`. После каждого шага берется центральный бит; каждые 32 бита объединяются в число через `word = (word << 1) | bit`.
- Строка Правила 30 хранится в битах одного целого числа и обновляется побитовыми операциями. Полная история не сохраняется. Для получения 2^24 чисел выполнено **2^29 = 536 870 912 шагов**.
- Для каждого генератора записан двоичный файл из 2^24 беззнаковых 32-битных чисел: **64 МиБ**, по 4 байта на число. Файлы и журналы находятся в `data/prng/`.
- `assert` проверяют правильность формул, реализацию Правила 30, упаковку битов и запись файлов. **DieHarder проверяет статистические свойства** последовательностей. В эксперименте выполнены два теста, Birthdays и Binary Rank 32×32, с параметром `-p 5`.

| Генератор | Birthdays: p-value / оценка | Binary Rank 32×32: p-value / оценка |
|---|---|---|
| ЛКГ | 0,99320508 / PASSED | 0,76185391 / PASSED |
| Python `random` | 0,97415423 / PASSED | 0,99755408 / WEAK |
| Правило 30 | 0,35440977 / PASSED | 0,96042416 / PASSED |

- **PASSED** — тест не обнаружил значимого отклонения при выбранных настройках. **WEAK** — пограничный результат, требующий проверки на новых данных. p-value не является оценкой качества по принципу «чем больше, тем лучше».
- В журналах не обнаружено сообщений о повторном чтении файлов. Если DieHarder сообщает `rewound N times` при N > 0, файл используется повторно; для надежной проверки нужно увеличить объем данных.
- Доля единиц около 0,5 не доказывает случайность: `010101…` тоже содержит половину единиц. Два пройденных теста не доказывают превосходство ЛКГ над Mersenne Twister или пригодность генератора для криптографии.

## Общий вывод по лабе

Простые детерминированные правила могут порождать периодический фон, движущиеся структуры и последовательности со сложными статистическими свойствами. Правило 110 показывает движение и взаимодействие локальных структур; машина Тьюринга — вычисление через последовательные команды; Правило 30 — получение битов из эволюции автомата. Численные результаты зависят от начальных условий, границ и времени наблюдения. Проверки кода подтверждают корректность реализации, а выбранные статистические тесты позволяют судить только о проверенных свойствах конкретных последовательностей.
